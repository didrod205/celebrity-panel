## 관찰한 한계

- 01과 02는 첫 실행에서 8,013자와 12,731자로 분량 기준(각 5,000자, 9,000자)을 넘었습니다. 턴이 길었고 각주가 대사를 되풀이했으며 02의 모드 표가 같은 내용을 두 번 썼기 때문입니다. 턴 길이, 각주, 표 규칙을 고친 뒤 다시 생성한 결과가 여기 실린 5,548자와 8,566자입니다.
- 01은 링크 주소까지 세면 5,548자로 제안값 5,000자를 548자 넘습니다. 화면에 보이는 글자는 4,735자입니다. 08은 링크 주소까지 세면 5,659자로 "5,000자 안팎"보다 길고, 화면에 보이는 글자는 5,009자입니다.
- 03과 05~09는 최종 규칙으로 생성한 답변이고 측정한 기준을 모두 충족했습니다. 이 중 03, 05, 06, 07은 이전 규칙으로 만든 첫 생성본을 이 답변으로 바꿔 실었습니다. 회의록 사례의 분량은 2,000~8,600자 안팎이고, 댓글만 받은 06은 1,222자입니다.
- 사례 8건(처음 6건과 `/redteam`, `/ask`)을 모델 하나(Claude Opus)로 돌린 결과입니다. 다른 모델이나 다른 입력에서 같은 품질이 나오는지는 확인하지 않았습니다.
- 블라인드 말투 테스트는 01의 첫 실행본과 재실행본에만 했고, 서브에이전트 한 번의 추정입니다. 패널 명단에 역할 설명이 있어 관심사로도 화자를 짐작할 수 있습니다. 나머지 답변에는 하지 않았습니다.
- 턴 길이와 문장 수는 휴리스틱으로 센 값입니다. 문장부호 없이 이어지는 문장은 적게 셀 수 있습니다.
- 평가표 21개 사례 중 일부만 돌렸습니다. `/jury`의 허위 주장 차단, `/customer`, `/future` 등은 이 예시에 포함되지 않았습니다.
