# 실제 사용 예제

아래는 입력과 예상 산출물의 축약 예시다. 모델 실행 로그나 실존 인물의 실제 발언이 아니다. Codex에서는 `$celebrity-panel`, Claude Code에서는 `/celebrity-panel`을 앞에 붙인다.

## 사업 회의 + Wildcard

입력: `/meeting /wildcard AI가 블로그 글을 자동 작성하는 서비스를 만들고 싶어. 4명으로.`

패널 예: 베이조스 — 반복 사용, 버핏 — 비용과 위험, 마윈 — 고객 과업, 미야자키 — Wildcard·관찰.

회의록 일부(합성 대사):

**진행자** 오늘 안건은 블로그 자동 작성 서비스이고, 고객은 아직 없다고 가정할게요. 베이조스 님부터요.

**베이조스** 고객이 다음 달에도 이걸 다시 쓸 이유가 뭔지부터 보고 싶어요. 생성한 글 수 말고 실제로 발행한 글 수로요.

**미야자키** 잠깐만요. 그 글을 읽는 사람을 실제로 본 적 있으세요? 빨리 나온 글보다 그 가게 냄새가 나는 글을 원할 것 같은데요.

**베이조스** 미야자키 님 말을 지표로 바꿔 보죠. 사장님이 고친 시간과 직접 넣은 사진 수를 같이 재면 돼요.

**버핏** 다만 숫자는 아직 하나도 없어요. 다섯 곳 정도로 작게 해 보죠, 숫자는 제안이고요.

작은 실험: 가정한 고객에게 자동 초안과 편집 지원 버전을 보여주고 실제 수정 과정과 선택 이유를 관찰한다. 작품 창작과 상업 블로그 운영의 차이는 정리에 한계로 남긴다. 프레임 근거: [미야자키 프로필](../people/hayao-miyazaki.md), [베이조스 프로필](../people/jeff-bezos.md).

## 파인만의 외부 질문

입력: `/meeting /wildcard 개인 창업 아이디어를 검토해줘. 파인만을 외부 질문자로 넣어줘.`

파인만에서 영감받은 관점은 좋아할 것이라는 설명이 틀렸음을 드러낼 관찰이 무엇인지 묻는다. 진행자는 이를 고객의 실제 선택을 관찰하는 실험으로 바꾼다. 물리 실험과 구매 행동의 차이·제약은 남긴다. [프로필과 공개 연설 근거](../people/richard-feynman.md).

## 공개 준비 심사

입력: `/jury AI가 완벽한 최신 법률 답을 보장한다고 랜딩페이지에 썼어. 실제 검증은 아직 없어.`

예상 판정: **공개 부적합 — 제공한 소개문의 검증되지 않은 보장 표현**. 제품 전체 심사를 했다고 말하지 않는다. 주장을 검증 가능한 범위로 수정하고, 남은 중요 근거가 없으면 재심은 보류한다. 심사 결론으로 페이지를 실제 게시하지 않는다.

입력: `/jury 아이디어는 연차 추천이야. 아직 화면도 소개문도 없어.`

예상 판정: **보류 — 공개할 자료와 사용 흐름 근거 부족**. 최초 고객·소개문·데모 수준을 정하고 다음 검증을 제안한다.

## 가정 실패 회의

입력: `/postmortem 연차 날짜 추천 앱이 6개월 뒤 실패했다고 가정해줘.`

예시 경로: 추천이 실제 휴가 승인 조건을 놓침 → 추천 실행 불가 → 반복 사용 부재. 다른 경로로 계절적 수요·유통·운영 비용 등을 확인할 가설로 제시한다. 회사마다 승인 제약을 실제 인터뷰로 확인할 때까지 원인이라고 확정하지 않는다.

## 자산을 살리는 Pivot

입력: `/pivot 연차 추천 알고리즘은 유지하고 사업 모델을 3개 제안해줘.`

| 모델 | 고객·지불자 | 제공 방식·수익 | 유지할 자산 | 첫 검증 |
|---|---|---|---|---|
| 개인 일정 최적화 | 개인 사용자 | 셀프서비스·구독 가설 | 추천 엔진 | 유료 선택 이유 관찰 |
| 팀 휴가 계획 도구 | 팀·관리자 | 조직 라이선스·팀 일정 | 추천 엔진 | 팀 단위 수작업 파일럿 |
| 여행 계획 파트너 도구 | 여행 파트너 | 통합·라이선스 가설 | 날짜 추천 엔진 | 파트너가 통합할 과업 확인 |

세 모델은 가설이며 수익과 계약을 보장하지 않는다. 고객·수익·운영의 차이와 비용을 비교하고 사용자의 제약에 맞는 하나부터 검증한다.

## 연쇄 실행

입력: `/postmortem /pivot /jury /wildcard 현재 블로그 생성 아이디어를 검토해줘.`

실패 가설이 대안의 변경 이유로 전달되고, 그 대안의 공개 자료가 없으면 jury는 보류한다. 외부 인물은 각 단계마다 추가되는 것이 아니라 패널 구성 전체에서 한 명이다.

## 짧은 일상 입력

입력: `/mentor 오늘 첫 버전을 만들었는데 아무도 안 들어왔음. 댓글만.`

예상: 3명의 다른 프레임으로 각 1~2문장. 성과를 인정하고 노출·첫 사용·반복 사용을 구분해서 다음 확인을 제안한다. 방문자 0명에서 제품의 재방문율을 이미 안다고 단정하지 않는다.
