# 패널 선정

목적·주제·제약을 한 문장으로 정리하고 서로 다른 검토 축을 고른다. 역할은 가상 회의의 담당 축이며 실제 인물의 직함을 뜻하지 않는다.

| 역할 | 담당 축 |
|---|---|
| Visionary | 목표와 장기 가능성 |
| Operator | 실행·운영·인력·제약 |
| Investor | 경제성·시간·손실·기회비용 |
| ProductThinker | 사용자 경험·문제·핵심 |
| Contrarian | 전제·반례·누락된 관점 |
| CustomerAdvocate | 사용자 필요·접근성·행동 |
| Ethicist | 영향받는 사람·설명 책임·부작용 |

`people/catalog.json`은 후보 목록이다. `domains`는 활동 분야, `roles`는 회의에서 적용할 수 있는 축이다. 감독에게 창작 관점을 맡겨도 투자 전문성을 부여한 것은 아니다. `signature_question`은 현재 문제의 구체적 변수에 맞춰 사용한다.

우선순위: 사용자 지정 → 질문 관련 근거 → 서로 다른 프레임 → 지역·분야 다양성. 지정 인물만으로 충분하면 추가를 강제하지 않는다. 동일 인물을 두 역할로 복제하지 않는다. 국가를 채우려고 근거 없는 전문가를 만들지 않는다.

`/random`은 필요한 역할별로 적합한 후보 중 예상 밖의 조합을 고른다. 균등 추출·난수를 보장하지 않으며 실제 난수가 없으면 추첨했다고 말하지 않는다. 사용자 지정 인물·인원은 유지한다. `/wildcard`가 있으면 분야가 다른 정확히 한 명 조건을 마지막에 적용한다.

선정 이유는 패널 소개 줄에 쓰지 않고 대화에서 드러낸다. Wildcard만 소개 줄에 본래 분야와 선정 이유를 한 구절로 붙인다. 직전 패널과 대화의 제약을 참고하되 대화 밖의 기록·지속 기억을 전제로 하지 않는다.

고객 유형은 유명인과 별도의 합성 역할이다. 나이·직업만으로 성격을 정하지 않고 과업·환경·예산·대안·도입 장벽을 가정으로 표시한다. 고객 역할도 총원 최대 7명에 포함한다.
