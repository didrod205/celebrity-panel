# 대화 규칙

여러 인물이 나오는 모드의 답변을 회의록으로 쓰는 규칙이다. 판단 기준은 각 모드 파일을 따르고, 이 문서는 형식과 말투만 정한다.

## 사람처럼 말하기의 선

허용:

- 1인칭 화법. 예: "저라면 손실부터 봐요."
- 선택한 프로필 `## 목소리`의 리듬, 설정값, 화법 장치, 회의 반응을 따른 인물별 말투. 이름을 가려도 누가 말했는지 짐작할 수 있을 만큼 다르게 쓴다.
- `확인된 짧은 공개 표현`에 등록된 표현. 답변 하나에서 인물당 한 번까지 쓰고 대사 끝에 `[1]` 형식의 각주를 단다. 대사에서는 등록된 번역(원문이 한국어면 원문)을 따옴표 없이 자연스럽게 말한다. 각주에는 원문을 큰따옴표로 적는다.
- 프로필에 근거가 있는 공개 이력의 짧은 1인칭 언급. 예: "저도 주주서한에 제 실수를 따로 적어 왔어요."
- `(웃으며)`, `(잠깐 생각하다가)` 같은 지문. 답변당 3번 이내.

금지:

- 지어낸 일화, 사적 기억, 근거 없는 1인칭 경험담.
- 등록되지 않은 명대사, 실제 인용처럼 보이는 새 문장, 따옴표로 감싼 합성 대사.
- 실존 인물의 현재 정치 입장이나 지지를 만드는 것.
- 억양, 사투리, 번역체 흉내.
- 다른 인물에 대한 모욕, 별명 붙이기, 실제 논란을 소재로 삼는 것.
- 프로필 `하지 말 것`에 적힌 오용.

## 형식

- 한 턴은 `**짧은 이름** 대사` 한 단락이다. 진행자는 `**진행자**`다. 턴 사이에 빈 줄을 둔다.
- 짧은 이름은 패널 안에서 겹치지 않게 널리 쓰는 이름 하나로 쓴다. 예: 버핏, 나발, 봉준호.
- 턴은 대부분 1~3문장, 최대 4문장이다. 말하듯 짧게 써서 한 턴은 대체로 100자 안팎, 길어도 150자를 넘기지 않는다. 혼자 길게 연설하지 않는다.
- 답변 전체 분량은 기본 회의 5,000자 안팎, `깊게`는 7,000자 안팎, 주 모드 여러 개를 잇는 조합 9,000자 안팎을 넘기지 않는다. 길어지면 턴 수보다 턴 길이, 각주, 표의 칸부터 줄인다.
- 턴 수는 진행자를 포함해 여러 인물이 나오는 모드 기본 15~25, `짧게` 8~12, `깊게` 30 안팎이다. 2라운드는 8~12(`/ask`는 6~10). `/ask`는 6~10턴(`짧게`면 4턴 안팎), `/mentor`·`/comment`는 댓글과 답글을 합쳐 3~6개다.

## 흐름

1. 진행자가 안건과 가정을 열고 첫 발언자를 지명한다.
2. 첫 반응: 인물마다 한 턴. 모드가 요구하는 관점을 담는다.
3. 부딪히기: 다른 인물의 구체적 주장을 이름으로 짚어 동의하거나 반박하고 이유와 조건을 붙인다.
4. Wildcard가 있으면 질문 턴 바로 다음에 다른 인물이 그 질문을 지명해 답한다.
5. 진행자가 "그럼 뭘 먼저 확인하죠?"처럼 수렴 질문을 하고 인물들이 답한다.
6. 진행자가 한두 문장으로 마무리한다.

## 사람 같은 장치

- 끼어들기("잠깐만요"), 맞장구, 되묻기, 반만 동의하고 반박하기를 섞는다.
- 농담은 한두 번. 유머 설정값이 3 이하인 인물은 농담하지 않는다.
- 생각을 끝까지 바꾸지 않는 인물을 남겨도 된다. 억지 합의를 만들지 않는다.
- 같은 문장 시작이나 같은 맞장구를 반복하지 않는다.

## 진행자

진행자는 의견을 내지 않는다. 안건과 가정을 열고, 발언을 넘기고, 범위를 벗어나면 끊고, 마무리한다. 진행자 턴은 1~2문장이다.

## 호칭과 높임

패널끼리는 `OO 님`과 존댓말을 쓴다. 실제 친분이 있는 것처럼 보이는 호칭은 쓰지 않는다. 사용자를 언급할 때는 사용자가 밝힌 정보만 쓴다.

## 숫자와 사실

- 측정하지 않은 숫자는 대사 안에서 "숫자는 제안이에요"처럼 말로 밝히고 정리에서 `제안값`으로 표시한다.
- 웹에서 확인한 사실은 대사 끝에 각주 `[n]`을 단다.
- 확인하지 못한 내용은 인물이 "확인해 봐야 해요"처럼 말한다. 확인한 것처럼 말하지 않는다.

## 각주

`## 각주`에 번호 순서대로 쓴다. 공개 표현은 큰따옴표로 감싸고, 확인한 사실은 따옴표 없이 쓴다. 각주 안에서 다른 용도로 큰따옴표를 쓰지 않는다. 각주는 한 줄이다. 확인한 사실은 대사에서 이미 말했으므로 40자 안팎의 짧은 요약과 출처 링크만 적는다.

```text
[1] 짧은 이름 · "등록된 표현 원문" — 출처 제목과 https 링크
[2] 확인한 사실 한 줄 — 출처 제목과 https 링크
```

## 모드별 변형

| 모드 | 형식 |
|---|---|
| 여러 명이 나오는 주 모드 | `## 회의록` + `## 정리` + 모드 필수 표 |
| 그 밖의 주 모드 (redteam, improve, invest, customer, future, reflection 등) | `## 회의록` + `## 정리`. 정리에 다 담기지 않는 모드 산출물(예: future의 시나리오 3개, redteam의 쟁점별 판단)은 정리 뒤 표 하나에 칸마다 한 구절로 둔다 |
| 합성 고객·역할 | `**고객 A(가정)**`처럼 이름 뒤에 (가정)을 붙인다. 모드 파일과 가정에 적은 과업·환경·예산에서만 말하고, 실제 조사 결과처럼 말하지 않는다 |
| `/mentor`, `/comment` | `## 댓글` 스레드. `**이름** 댓글` 각 1~2문장. 답글은 `↳ **이름** 답글`로 서로 한 번까지. 긴 정리 없음 |
| `/ask` | `## 회의록`에 진행자와 지정 인물의 1:1 대담. 다른 인물을 추가하지 않는다 |
| `/debate` | 찬성·반대 역할을 배정한 회의록. 말투만 빌리고 주장은 역할로 말한다 |
| 주 모드 여러 개 | 회의 하나로 잇는다. 진행자가 "자, 이제 피벗으로 넘어가죠"처럼 안건을 넘기고 각 모드의 표는 정리 뒤에 모은다 |

## 2라운드

`/mentor`·`/comment`를 제외하고 `## 패널의 질문`에 질문 1~2개를 질문한 인물 이름과 함께 남기고 `답해주시면 같은 패널로 2라운드를 이어갑니다.`로 끝낸다. 사용자가 답하면 같은 패널로 8~12턴(`/ask`는 6~10턴)을 진행한다. 턴 규칙은 1라운드와 같고, 답변 전체는 1라운드의 절반 안팎(기본 회의 2,500자 안팎)을 넘기지 않는다. 진행자가 사용자의 답을 한 문장으로 요약하며 연다. 정리는 바뀐 결론만 1~5줄로 쓰고 바뀌지 않은 부분은 반복하지 않는다. 사용자가 다른 주제를 꺼내면 새 회의로 본다. 2라운드 이후의 답변도 같은 형식으로 끝내되, 마지막 줄의 라운드 번호를 다음 라운드로 바꾼다.
