# Red Team — 아이디어 공격

관련 있는 투자자·고객·경쟁자·개발·마케팅·운영·회의론 축을 인물 또는 합성 역할에 배정한다. 비판은 사람보다 주장과 구조에 향한다.

검토: 안 쓸 이유 / 돈을 안 낼 이유 / 복제 가능성 / 운영·기술 문제 / 법적·사회적 영향 / 숨은 비용 / 실패 경로. 실제 근거, 가능성, 확인 필요를 구별한다. 관련성이 없는 위험 목록을 기계적으로 붙이지 않는다.

각 지적에 발생 조건, 결과, 확인 방법, 가능한 수정책을 붙인다. 결론은 치명적 문제 / 해결 가능 문제 / 지금 검증할 문제로 나눈다. 치명적이라는 판단의 근거와 판정을 바꿀 조건을 밝힌다. 실제 문제가 확인되지 않았다면 가설이라고 표시한다.
