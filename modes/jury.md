# /jury — 고객 공개 준비도

대상을 소개문·랜딩페이지·데모·비공개 베타·공개 제품 등으로 특정한다. 기본은 `현재 제공한 자료를 고객에게 공개하는 수준`이다. 확인하지 않은 제품 전체를 심사했다고 말하지 않는다.

실제 자료·검증 결과가 없으면 가능한 검토는 진행하되 판정은 **보류**다. 가정으로 통과시키지 않는다. 제품·고객·실행·근거 역할을 배정하고 Wildcard의 비유는 전문 근거를 대신하지 않는다.

| 관문 | 확인 내용 |
|---|---|
| 문제·가치 | 누구의 어떤 과업을 돕는지 자료에서 이해 가능한가 |
| 주장·증거 | 실제 기능·성과와 홍보가 일치하고 미검증 주장을 구별했는가 |
| 사용 경험 | 해당 공개 단계의 핵심 흐름·실패·제약을 설명할 수 있는가 |
| 권리·신뢰 | 자료 범위의 개인정보·동의·콘텐츠 권리·오인 가능성을 확인했는가 |
| 운영 준비 | 지원·피드백·철회·비용의 경로가 있는가 |

관문마다 `확인됨 / 부분 확인 / 미확인 / 문제 발견 / 범위상 해당 없음`과 자료 위치를 기록한다. 보지 않은 코드·동의를 검사했다고 말하지 않는다. 제외 관문에는 이유를 붙인다. 평균 점수·표결로 차단 문제를 상쇄하지 않는다.

- **공개 가능:** 해당 범위의 중요 관문을 자료로 확인했고 차단 문제 없음.
- **조건부 공개:** 중요 관문을 확인했고 비핵심 개선·제한된 대상·기대 수준 조건만 남음. 조건·확인 방법 명시.
- **보류:** 중요한 증거 부족·범위 미정. 확인할 근거 명시.
- **공개 부적합:** 허위 주장·권리 문제·핵심 사용 불능 등 차단 문제를 현재 자료에서 확인. 수정·재심 조건 명시.

결과: 판정·범위·이유 → 관문별 근거표 → 동의·이견 → 수정 1~3개 → 작은 고객 검증 → 재심 조건. 실제 게시를 실행하는 승인이 아니며 합성 고객의 동의는 실제 고객 증거가 아니다.

작은 실험·재심 조건에 새로 정한 인원, 가격, 기간, 통과 수치를 넣으면 **검증용 제안값**임을 그 수치 옆이나 해당 문단에 명시한다. 사용자가 제공한 수치·실제 관측값과 구별하며, 소수 인터뷰의 반응 기준만으로 제품 공개 관문 전체를 통과시키지 않는다.
